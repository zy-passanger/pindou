# ADR-0005：OKLab 色差匹配、两遍限色与可选抖动

- 状态：Proposed（架构评审）
- 日期：2026-11-05
- 相关：architecture.md §6、§8

## 背景

图片转图纸需要把任意颜色映射到 MARD 真实色卡；人眼对色相/明度的感知不均匀，直接 RGB 距离会选错。还要支持最多颜色数、背景移除和可选抖动，且在 40k–90k 格上足够快。

## 决策

- 重采样在**线性光**下做面积平均，避免发灰。
- 色差在 **OKLab** 空间用欧氏距离平方；色卡 OKLab 预计算并缓存。
- 匹配后支持“最多 N 色”：
  1. 统计已匹配颜色用量；
  2. 保留用量前 N；
  3. 其余格重新匹配到保留色中的最近色。
  确保最终 distinct 色数 ≤ N。
- 可选 **Floyd–Steinberg** 抖动；仅在允许色卡内扩散误差；默认关闭。
- 背景移除：alpha 阈值 + 与背景色的 OKLab 距离容差；背景默认取四角众数。
- 输出 `Uint16Array` 索引 + 统计；确定性（同输入同参数同色卡同结果）。
- 允许色 = 我的色卡 ∩ 工程色卡；为空时阻止转换并提示。

## 结果

**正面**

- 比 RGB 距离更符合视觉，接近真实豆子色。
- 291 色 × 90k 格在 Worker 中可接受；无需复杂索引。
- 限色规则可解释（按用量保留），适合备豆。
- 确定性便于测试与复现。

**负面**

- OKLab 与 CIEDE2000 不完全一致；极端颜色可能有差异。
- 两遍限色不是全局最优（不如 k-means），但更稳定/可解释。
- 抖动会改变单格颜色，可能增加备豆复杂度。

## 备选方案

| 方案 | 不选原因 |
|---|---|
| RGB 欧氏距离 | 感知不均匀，选色差 |
| CIEDE2000 | 更准但更慢；v1 不做，保留升级 |
| 中位切分/ k-means 再映射 | 色卡离散，易出现映射偏差；限色不可解释 |
| 无抖动 | 照片渐变会有色带；保留为可选 |

## 说明

- 色卡 HEX 是屏幕参考；匹配只对这些参考值负责，实物差异由数据校准解决。
- 如性能不足，再加 kd-tree/3D LUT；接口不变。
- 抖动 + 限色顺序固定：先确定限色集合，再抖动；避免色数膨胀。
