# ADR-0002：纯前端 PWA、本地优先、无后端

- 状态：Proposed（架构评审）
- 日期：2026-11-05
- 相关：architecture.md §1、§3、§10

## 背景

目标用户是平板/手机上的拼豆玩家；核心操作是绘制、图片转换、统计和打印。没有账号、协作、云同步需求；用户明确要求数据保存在本地。引入后端会带来部署、隐私、成本和离线复杂度。

## 决策

- 产品为**纯前端 PWA**：React + Vite 构建静态资源，部署到任意静态托管。
- 无后端、无账号、无遥测；所有数据在浏览器本地（IndexedDB）。
- 使用 Service Worker 预缓存应用壳、色卡与图标，离线可用。
- 使用 `navigator.storage.persist()` 请求持久化；提供 `.pindou.json` 工程文件导入/导出作为备份。
- 不使用 Electron/Tauri 作为 v1 形态；保留后续用 Tauri 包装的可能。

## 结果

**正面**

- 零运维、零服务器成本；隐私好；离线可用；安装到主屏接近原生。
- 开发/发布简单，单页应用；图片/PDF 全部本地计算。
- 数据不离开设备，符合“本地保存”的要求。

**负面**

- 无跨设备/云备份；IndexedDB 可能被系统清理，必须引导用户导出备份。
- iOS PWA 限制（安装入口、后台、存储策略）需要单独提示与测试。
- 无服务端兜底，性能受设备限制。

## 备选方案

| 方案 | 不选原因 |
|---|---|
| 后端 + 账号 | 增加运维/隐私/离线复杂度；当前无需求 |
| Electron/Tauri | 需要打包/签名/更新链；PWA 已满足触控/离线 |
| 原生 iPad/Android | 双端成本高；设计稿是 Web 形态 |
| 仅本地 HTML 文件 | 无安装/离线缓存/存储管理，不适合长期使用 |

## 说明

- 备份是本地优先的必备能力，不是附加功能；工程文件入口在 v1 必须有。
- 若未来加云同步，应作为可选增量，不改变本地优先的数据模型。
